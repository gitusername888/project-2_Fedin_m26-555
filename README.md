# PrimitiveDB

PrimitiveDB — простая консольная реляционная база данных с SQL-подобным интерфейсом.
Данные хранятся в JSON-файлах, метаданные таблиц — в `db_meta.json`.

## Возможности

- Создание, просмотр и удаление таблиц
- Вставка, выборка (с условием WHERE), обновление и удаление записей
- Строгая типизация данных (`int`, `str`, `bool`)
- Автоматическая генерация первичного ключа `ID:int`
- Кэширование результатов запросов `select`
- Замер времени выполнения операций
- Подтверждение опасных операций (drop_table, delete)
- Красивый вывод таблиц (prettytable)

## Требования

- Python 3.10+
- Библиотеки: `prettytable` (см. `requirements.txt`)

## Особенности синтаксиса

- **Типы данных**: при создании таблицы поддерживаются только `int`, `str` и `bool`.
- **Значения**: строковые значения в командах `insert` и `where` рекомендуется брать в кавычки (например, `"John Doe"`).
- **Логические значения**: для типа `bool` допустимы `true/false`, `1/0`, `yes/no`.
- **ID**: первичный ключ `ID` генерируется автоматически при вставке, указывать его в `insert` не нужно.
- **SELECT без условия**: команда `select from users` вернёт все записи таблицы.

## Особенности реализации

### Строгая типизация

В отличие от многих NoSQL-хранилищ, MinimalDB строго проверяет типы данных.
При выполнении `select` и `update` сравнение происходит по правилу: должны совпадать **и тип, и значение**.
Запрос `where age = "25"` (строка) не найдёт строку, где возраст записан числом `25` (integer).

### Кэширование

Движок использует механизм кэширования на замыканиях: фабрика `create_cacher()` возвращает
внутреннюю функцию `cache_result(key, value_func)`, которая хранит словарь кэша в своём замыкании.

- Результаты выборок (`select`) сохраняются в оперативной памяти.
- Ключ кэша строится на основе имени таблицы и **отсортированных** условий WHERE,
  поэтому порядок условий в запросе не влияет на попадание в кэш.
- Повторный идентичный запрос подтягивает данные из кэша, не пересчитывая их.

### Логирование

Декоратор `@log_time` автоматически замеряет время выполнения тяжёлых операций
(`insert`, `select`, `update`, `delete`) и выводит его в консоль — удобно для отладки производительности.

### Безопасность

Операции, которые могут привести к потере данных (`drop_table`, `delete`), обёрнуты
в декоратор `@confirm_action`. Перед выполнением скрипт попросит ввести подтверждение.
Ошибки БД перехватываются декоратором `@handle_db_errors` и выводятся в понятном виде,
не прерывая работу консоли.
